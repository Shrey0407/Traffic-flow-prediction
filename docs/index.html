Machine learning project · PEMS-BAY · San Francisco Bay Area

Predicting Road Speed 2 Hours Ahead

Given recent speeds, weather and the calendar, how well can a model forecast the average speed of a freeway segment at hour t + 2, and by how much does it improve on two simple baselines?

Headline result Hour-of-week baseline: 2.342 km/h validation MAE, 2.436 km/h test MAE. Trained-model results appear here once the final test run is exported.

02Research question

What is being predicted, and why

Drivers, freight operators and traffic managers plan around conditions that will exist later, not the ones they see now. This project asks whether a model that sees only information available at hour t can predict the average speed on a road segment at hour t + 2 more accurately than the two forecasts that need no learning.

Row unit
One road sensor (segment) at one hour.
Target
Average speed on that segment at t + 2, in km/h.
Information
Recent speeds of the segment and its nearest neighbours, weather, holiday flag, hour and weekday, all known at t.
Primary metric
Mean absolute error (MAE) in km/h; lower is better.
03Data

PEMS-BAY freeway detectors

The speed table comes from Caltrans PeMS Bay Area detectors, distributed with the DCRNN repository: 325 sensors, 5-minute readings, January to June 2017, in miles per hour. This study uses 8 segments chosen for coverage and explainability and fixed before any modelling. Weather is from Open-Meteo and holidays from the Python holidays package.

Quality checks found the data nearly complete. Missing readings are stored as zero (0.003% of all values) and are treated as missing. Of the hourly rows, 0.023% are absent: the single hour skipped by the March daylight-saving change, identical for all segments. There are no duplicate rows and no missing weather values.

04Preprocessing

From raw readings to a modelling table

  1. Zeros to missing. A zero speed marks a failed reading, not a standstill. At one moment (2017-06-15 01:00) 67% of sensors read zero together, which is a feed outage.
  2. Units. Miles per hour are converted to km/h (× 1.609344).
  3. Hourly resampling. Twelve 5-minute readings are averaged per hour, and the hour is kept only if at least 9 of 12 exist.
  4. Neighbours. Each segment receives the speed of its nearest sensors by latitude/longitude distance. This is straight-line distance, not road connectivity.
  5. Weather and calendar. Temperature, humidity and precipitation are merged by hour; a US/California holiday flag, hour and weekday are added.
  6. Leakage rules. Every feature uses data up to hour t only. An automated test (src/tests) enforces this.
05Baselines and methods

Two baselines, seven models

Baselines

  • Persistence. The speed in two hours equals the speed now. It needs no training and is the reference for skill.
  • Hour-of-week mean. The training-set average for the same weekday and hour. It captures the weekly rhythm without learning anything else.

Models

  • Linear regression and Ridge and Lasso: interpretable linear baselines; Ridge and Lasso add L2 and L1 penalties to control overfitting and to drop weak features.
  • Decision tree: captures thresholds and interactions such as “weekday and 08:00” without manual features.
  • Random forest: averages many trees to reduce variance.
  • XGBoost: gradient-boosted trees that fit residual errors step by step.
  • Voting ensemble: averages the predictions of several models.

Hyperparameters were tuned on training data only; the model with the lowest validation MAE was chosen.

06Evaluation

A chronological split without leakage

train 60%
val 20%
test 20%

Blocks are in time order. Narrow bars mark the 2-hour gaps.

Because the target is two hours ahead, a row at the end of one block has a target that falls inside the next. A 2-hour gap between blocks removes that overlap, so no information about the test period reaches training.

  • The test set was used once, for the single selected model.
  • MAE (primary) and RMSE, both in km/h.
  • Skill = 1 − MAE / MAEpersistence; above 0 beats persistence.
  • A daily block bootstrap gives the 95% interval for the test MAE.

08Errors

Where the forecasts fail

lowhigh

Failure cases to examine

These are the specific situations where the data itself is unreliable or unusually hard. Each is checked against the model's errors once the final run is exported.

  1. Rush-hour onset (07–09 and 16–18, Tue–Thu). Speeds fall from about 107 to 77–90 km/h within hours. A forecast made two hours earlier sees free flow and must anticipate the drop.
  2. Frozen feed on segment 400100. The sensor repeats one value for 24 hours on 2017-04-20 and 2017-05-18 (also 12 hours on 05-30 and 06-06). Both features and target are wrong there, so errors on those days say little about the model.
  3. Network-wide feed outage on 2017-06-15 around 01:00. 67% of sensors read zero at once. Neighbour features are missing or distorted across the whole network.
  4. Daylight-saving day, 2017-03-12. The 02:00 hour does not exist; lag features that cross it point at the wrong clock hour.
  5. Rain. Wet hours are rarer in the sample, so error estimates for them are noisier. Use the “Rain only” condition above.
09Limitations

What this study cannot claim

  • Missing data. Zero-valued readings are treated as missing and the 9-of-12 rule discards thin hours. Outages affect features and target alike.
  • Frozen feed. Segment 400100 repeats values for up to 24 hours on several days. It was kept and flagged rather than repaired.
  • Geography. Eight segments on Bay Area freeways in one half-year. Results do not transfer to other cities, roads or seasons.
  • Neighbours by distance. Nearest sensors are chosen by straight-line distance, not by road connectivity or direction of travel.
  • No incidents or events. Crashes, roadworks and large events are not in the data. Weather is observed at t, not forecast.
  • Association, not causation. The model finds patterns that predict speed; it does not explain why speed changes.
10Conclusion

Did the models beat the baseline?

The hour-of-week baseline is strong: it reaches 2.342 km/h validation MAE (2.436 on test), less than half of persistence at 5.366 (5.008 on test). The question is therefore not whether a model can beat persistence, but whether it can improve on a weekly average.

Pending the final test run: the selected model, its test MAE against the 2.436 km/h baseline, the size of the improvement with its 95% interval, and a plain statement of what that does and does not show.

11Reproduce

Run it yourself

Python 3.11 or newer; seed random_state=0 throughout. Use pandas below version 3, because pandas 3 cannot read the HDF5 file through PyTables.

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python src/01_build_dataset.py
python src/02_features_split.py
python src/baselines.py
python src/03_train_select.py
python src/04_final_test.py
python src/05_export_site.py

pytest src/tests          # leakage checks
python -m http.server 8000 --directory docs

Download the two raw files into data/raw/ first, as described in data/raw/SOURCES.md.
